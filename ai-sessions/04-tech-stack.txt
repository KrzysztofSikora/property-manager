  Area: Runtime
  Choice: Node.js LTS
  Version: 24.x (24.21)
  Why: Active LTS. Node 26 isn't LTS yet.
  Runner-up and why it lost: Node 22: still supported, but Vitest 5, MSW 3 and
  React Router 8 need ≥22.12 anyway, and 24 is supported for longer.
  ────────────────────────────────────────
  Area: Running TS on the API
  Choice: Node's built-in type stripping (erasableSyntaxOnly)
  Version: —
  Why: No tsx and no build step. I tested it in a node:24 container through a
  pnpm-style workspace symlink, and it works.
  Runner-up and why it lost: tsx is the safer, better-known option. We don't
  need
  it, though: no enums or decorators, and codegen can emit enumsAsTypes.
  ────────────────────────────────────────
  Area: Package manager / layout
  Choice: pnpm workspaces: apps/api, apps/web, packages/shared
  Version: pnpm 10+
  Why: shared holds the zod address schema, state list and error codes, so the
  UI
  form and the API apply the same rules (FR-07, FR-13).
  Runner-up and why it lost: npm workspaces: one tool fewer, but slower, and
  missing dependencies aren't caught as strictly.
  ────────────────────────────────────────
  Area: GraphQL server
  Choice: GraphQL Yoga on node:http
  Version: 5.24
  Why: Error masking is on by default, which fits FR-10 AC2. Errors carry codes
  through extensions.code. Few dependencies.
  Runner-up and why it lost: Apollo Server 5: better known, but it needs graphql

  16 and an Express/standalone layer. Yoga does the same here with less.
  ────────────────────────────────────────
  Area: graphql-js
  Choice: graphql
  Version: 16.14
  Why: Mature, and the whole ecosystem supports it.
  Runner-up and why it lost: 17.0: only 4 months old and Apollo can't use it
  yet.
  Nothing in it helps us.
  ────────────────────────────────────────
  Area: Schema approach
  Choice: SDL-first schema.graphql + GraphQL Code Generator
  (typescript-resolvers
  for the server, client-preset for the web)
  Version: cli 7.4
  Why: One schema file a reviewer can read, with types from resolver to React
  component.
  Runner-up and why it lost: Pothos (code-first): no codegen step on the server,

  but the contract is harder to read in review.
  ────────────────────────────────────────
  Area: Database
  Choice: PostgreSQL in Docker Compose
  Version: 18
  Why: A real unique index for concurrent duplicates (FR-08 AC2), jsonb for the

  concurrent writes worse and the brief expects a database service to start.

  Area: Data access
