● The plan review for F-02 (property-schema) is done. The verdict is ready to 
  implement with notes: nothing blocks it, but there is 1 major and 6 minor
  findings. The full review is in
  context/changes/property-schema/plan-review.md, and plan.md hasn't been
  changed.

  Major
  1. No test that the migrate command keeps the database URL secret. The plan
     says the command exits 1 on a config or migration error and never prints
     the URL. The URL can contain the password, but no test checks either claim.
     Suggested fix:
     - Run the command against an unreachable URL whose password is a sentinel
       value. Check that it exits 1 and that its error output doesn't contain
       the sentinel.
     - Also check that an invalid URL gives a config error and exit 1.

  Minor
  2. Phase order: the Phase 2 schema tests insert rows that collide with each
  other, but resetDb only arrives in Phase 3. Either move the database helpers
  into Phase 2, or have the schema test clear the table in beforeEach until
  resetDb exists.
  3. smoke.int.test.ts isn't in the Files list. The new harness.int.test.ts is
  meant to replace its app setup, but that file also holds the TR-25 test. The
  plan should say whether it is edited, renamed or deleted, and keep TR-25.
  4. The weather_data CHECK also accepts a JSON array. ["units","current"]
  passes the current check. Add jsonb_typeof(weather_data) = 'object', or record
  why the gap is accepted.
  5. The new import ban on src/db/** doesn't cover adapters. It covers resolvers
  and services only.
  6. The "missing required column → 23502" tests won't type-check as written. A
  Drizzle insert without the column fails the type check, and any is banned. The
  plan should say how the test builds that row.
  7. Mismatch with the test plan. The Cookbook in context/test-plan.md documents
  createTestApp({ weather }), but this plan builds createTestApp() with no
  options. The Cookbook update should mark the weather option as added in S-01.

  What checked out: every file and line the plan cites matches the repo. The
  Drizzle API claims match the current docs. Each part of the roadmap acceptance
  has an integration test. There is no context/lessons.md yet, so there were no
  lessons to check against.

  If you want, I can update plan.md with these fixes before you approve it.
