  Things research turned up that the plan now accounts for:

  - jsdom has no <dialog> support. Version 30.1.2 has no showModal() or close(),
    so the test setup adds them. To keep tests reliable, the dialog only exists
    on the page while it is open.
  - A test library is missing. The test plan's Cookbook assumes
    @testing-library/user-event, but it isn't installed. Phase 1 adds it, along
    with the web app's dependency on @property-manager/shared.
  - FR-12 AC5 is narrower than it reads. Every key weather field is required in
    the schema, and astro/air_quality only exist in raw, which S-04 doesn't
    fetch. So the only fields that can be missing are the description and the
    icon (empty lists), and that is what the AC5 test checks.
  - No mutation step for S-04. No Stryker target is touched; execute.ts doesn't
    change.

  One risk to settle during Phase 1: pinning the test time zone to UTC needs
  checking against when Intl first reads it. The plan has a fallback if the
  first approach doesn't hold.
