  Major
  1. Phase 2 will break a test the plan doesn't list. The FR-07 AC2 test at
     apps/api/test/integration/create-property.int.test.ts:136-147 creates a
     property with state: 'MA' using the default fake weather client. That fake
     returns region "Arizona", so the new region check will throw
     WEATHER_LOCATION_MISMATCH and the test will fail. To fix it, give that test
     a fake that returns 'Massachusetts' and add the test to Phase 2's file
     list.

  Minor
  2. The race test needs no new fake logic. A sequential test never reaches the
  in-memory repository's duplicate-key throw, because existsByAddress catches
  the duplicate first. The existing failInsert(new PropertyAlreadyExistsError())
  already covers that branch.
  3. The default-timeout test is weak. Checking the 5000 constant and that fetch
  gets a signal would still pass if the default weren't wired up. Spying on
  AbortSignal.timeout and checking it gets 5000 (or 50 when injected) would
  actually test it. Stryker would probably flag the gap otherwise.
  4. The District of Columbia check means handling the API key. The plan calls
  Weatherstack /current directly, which puts the key in a URL or shell command.
  Instead, after Phase 2, create a property with the DC address through pnpm 
  dev. That is still one call, and it goes through the create mutation as
  CLAUDE.md requires.
  5. Two scope nits:
  - The mutation run includes graphql/errors.ts, which the plan doesn't change.
    Either drop it or note that it's a deliberate re-check.
  - The new text() test handler has a status parameter that no planned test
    uses.

  The review found nothing else wrong:
  - The files, line numbers and library claims the plan cites match the repo.
  - Every acceptance criterion has a named test.
  - The plan follows the rules in lessons.md.
  - The concurrency test doesn't depend on timing.
