● I've written the S-01 plan to
  context/changes/create-property-with-weather/plan.md and set S-01 to planned
  in context/roadmap.md. Nothing is committed yet.

  Your decisions:
  - property(id) moves to S-01: a minimal version, so FR-05 AC1 ("a following
    property(id) returns the same data") is proven through the API. A malformed
    id returns null. S-03 keeps the FR-04 tests, the list and delete. I noted
    this move in both roadmap entries.
  - Failures before S-02: every Weatherstack failure returns
    WEATHER_UNAVAILABLE. S-02 adds the quota error, the config-error log and the
    full set of failure cases.
  - Scalars: graphql-scalars 2.0 for JSON and DateTime. It supports graphql 17.
  - Validation errors: BAD_USER_INPUT carries extensions.fields as a list of { 
    field, message }, so the S-05 form can show each field's reason.

  Design choices I made, all recorded in the plan:
  - New src/domain/ folder for shared types, interfaces and errors. Adapters
    aren't allowed to import from services/, so the interfaces can't live there.
    An ESLint rule keeps the new folder from importing any layer.
  - Converting the weather fields: one domain function validates the required
    weather fields in current and converts them to camelCase. Both the adapter
    and the repository use it.
  - Error masking: Yoga's default puts the original error and its stack trace
    into the response when NODE_ENV=development, which would break FR-10 AC2.
    The plan replaces it with our own function that never does this. That
    function is also the one place that maps domain errors to their codes.

  Phases:
  1. Shared address schema: the zod schema and normalizeAddress, proven by unit
     tests for FR-07 AC1–AC5 and FR-05 AC3.
  2. Domain and Weatherstack adapter: includes key redaction, MSW handlers and
     FakeWeatherClient, proven by unit and MSW tests.
  3. Repository and service: proven by service unit tests with fakes and a
     repository integration test.
  4. GraphQL wiring: schema, codegen, error handling and app wiring, proven by
     integration tests for FR-05 AC1, AC2, AC3 and AC6, FR-07 through the API,
     and FR-10 AC2.

  Human check in Phase 4: you run one real createProperty in GraphiQL. That uses
  one Weatherstack call from the quota.
