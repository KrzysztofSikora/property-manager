  What I checked before writing it: I ran drizzle-orm 0.45.3 and drizzle-kit
  0.31.11 against a throwaway postgres:18-alpine database, running the code as
  plain .ts the way the API does.
  - The case-insensitive address index generates the SQL we want. Two rows that
    differ only in case are rejected with pg error 23505.
  - uuidv7() works as the id default, and the ids it produces are version 7.
  - migrate() runs under Node's type stripping, and running it a second time
    does nothing.
  - A missing required value is rejected with 23502.
  - One surprise for S-02: when the database rejects a row, Drizzle wraps the
    error, and the pg error code is on error.cause, not on the error itself. I
    recorded this in the plan's Findings, and Phase 3 adds a note to the S-02
    entry in the roadmap.

  Your three decisions:
  - Id: UUID v7 from the database.
  - Database checks: besides required columns and the unique index, the database
    also checks lat/long ranges, a 5-digit zip, a 2-letter upper-case state,
    and that weather_data has both units and current.
  - Test helpers: the fake weather client (FakeWeatherClient) moves to S-01,
    where the weather client it imitates is designed. F-02 builds the database
    and data helpers.
