  - TS 7.0.2: typescript-eslint refuses TS 7 ("does not support TS 7.0") and

    - With that setup, TS 7 type-checked cleanly and type-aware lint caught any,

      unless you change it. Revisit once typescript-eslint supports TS 7 and
      the alias can go.

      type definitions that fail tsc (they errored under TS 7 here).

  3. Type-stripping rules: enforced by tooling, nothing to remember.
  - erasableSyntaxOnly makes tsc reject enums and parameter properties.
  - verbatimModuleSyntax makes it reject type imports written without import 
    type.
  - .js extensions on relative imports get past tsc but crash at runtime. A
    built-in ESLint no-restricted-imports regex rule catches them, so no plugin
    is needed.
  - Codegen gets enumsAsTypes: true and useTypeImports: true, so generated files
    also pass Node's type stripping.
