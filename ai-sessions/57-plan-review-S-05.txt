  Major
  1. maxLength can save a wrong zip without telling the user. When a user pastes
     text into a field with maxLength, the browser cuts it down and shows no
     warning. A pasted 852681 becomes 85268, passes the 5-digit check and is
     saved, which gets around FR-13 AC1. The suggested fix is to remove
     maxLength from Zip code and State and let addressSchema show its own
     messages.

  Minor
  2. The "no request sent" check is described wrongly. With MSW's
  onUnhandledFrame: 'error', the request is rejected but the test doesn't fail.
  What actually proves no request went out is the handler that records calls and
  expects zero.
  3. The renderWithProviders description is wrong. The helper has no <Routes>
  and doesn't expose its QueryClient. The hook test needs its own client, the
  way useDeleteProperty.test.tsx does it.
  4. The error-message table has a generic name but create-specific wording. For
  example, the INTERNAL_SERVER_ERROR message says "the property was not saved".
  The PROPERTY_NOT_FOUND entry is never used.
  5. One AC3 assertion will fail on letter case. The test looks for "upgrade the
  plan…" but the message starts with "Upgrade", so the match should ignore
  case.
  6. A partly unknown BAD_USER_INPUT loses a message. If the API names one known
  field and one unknown field, the unknown one is dropped and no form-level
  message is shown. The plan only has a fallback for when every field is
  unknown.

  The reviewer checked every file, symbol and line reference in the plan and
  found them accurate. The acceptance criteria trace to tests, and the plan
  doesn't contradict lessons.md.
