  example: the mismatch error carries both states in its message only, with no
  extra extensions, because FR-10 asks for nothing more. Here is the proposed
  shape:

  1. Weather failure classification. Adds WeatherQuotaExceededError. The adapter
     maps body codes 104 and 429 to quota. It maps 101, 105 and 403 to
     unavailable and writes a configuration-error log entry. Every other failure
     (another body error, HTTP status 429, non-2xx, network error, invalid
     JSON, schema failure) becomes unavailable. The timeout becomes injectable
     (default 5000 ms), and MSW gets a hang handler. Proven by an MSW it.each
     matrix on the adapter: FR-06 AC1–AC7, TR-01/02/10/11, plus a case where the

     createTestApp({ weather: 'msw' }) covers FR-05 AC5: each code is returned,
     the count doesn't change, and no secret appears.

     case-insensitive, against stateName) and WeatherLocationMismatchError,
     whose message names "AZ (Arizona)" and the returned region. The check runs
     after the weather call and before the insert. Proven by a unit table
     (exact, case, padding, DC, mismatch), service unit tests showing no insert
     on mismatch, and an integration test for FR-05 AC4. Human check: one real
     DC call to confirm the region string.
  3. Duplicate prevention. Adds PropertyRepository.existsByAddress (the same
     lower() expressions as the unique index). The service pre-checks before the
     weather call, and the repository maps a pg 23505 on
     properties_address_unique (found on DrizzleQueryError.cause) to
     PropertyAlreadyExistsError. Proven by FR-08 AC1 (case and whitespace
     variant, 0 weather calls) and AC2 (withBarrier(2) plus Promise.all: one
     success, one PROPERTY_ALREADY_EXISTS, count 1). AC3 is checked by deleting
     the row directly in the test DB, then creating it again. A repository
     integration test covers the 23505 mapping.

● I wrote the plan to context/changes/create-property-guards/plan.md, and S-02
  is now planned in context/roadmap.md.

  Phases:
  1. Weather failure classification.
     - Body codes 104 and 429 return WEATHER_QUOTA_EXCEEDED.
     - Body codes 101, 105 and 403 return WEATHER_UNAVAILABLE and write one
       error-level "configuration error" log line.
     - Everything else returns WEATHER_UNAVAILABLE.
     - The timeout can be passed in for tests; it stays 5000 ms by default.
     - Tests: a full MSW failure table at adapter level and end to end. One case
       puts the key inside Weatherstack's info text and inside a fetch error
       message, per your lesson on testing redaction.
  2. Region check. regionMatchesState runs in the service, after the weather
     call and before the save. A mismatch returns WEATHER_LOCATION_MISMATCH,
     with a message naming "AZ", "Arizona" and the region Weatherstack returned.
     Human check: one real call with a DC address.
  3. Duplicate prevention. existsByAddress runs before the weather call, using
     the same lower() expressions as the unique index. A pg 23505 on
     properties_address_unique maps to PROPERTY_ALREADY_EXISTS; any other
     database error is still masked. The race test uses withBarrier(2): both
     creates pass the pre-check and reach the insert, so it's the index that
     blocks the second one.
