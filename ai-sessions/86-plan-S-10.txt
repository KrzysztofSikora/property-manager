  The design, using your answers:
  - Command: pnpm seed sends the createProperty mutation to an API that is
    already running. The URL comes from SEED_API_URL and defaults to
    http://localhost:4000/graphql. The seed itself never touches the
    Weatherstack key or the database.
  - Order: it creates the properties one at a time, in list order, waiting 1.5 s
    after each successful create. The README says two calls within about a
    second can be rejected with HTTP 429.
  - On failure:
    - An address that already exists (PROPERTY_ALREADY_EXISTS) is skipped and
      costs no quota, so running it again is safe.
    - Any other error stops the run with exit code 1 and names the address and
      the error. That covers other API errors, an HTTP failure, an unreachable
      API or a malformed response.
  - Tests:
    - Unit tests mock the GraphQL endpoint and cover each stop and skip path.
    - One integration test runs the seed against the real app with the fake
      weather client. The first run should create 2 properties with 2 weather
      calls. A second run should skip both and make no new calls.
    - A tooling test proves nothing runs the seed automatically. It checks that
      the Compose files, Dockerfiles, CI, the git hook and the package.json
      scripts never mention it.
  - Docs: a "Demo data" section in the README, SEED_API_URL in .env.example,
    test-plan row TR-29, and apps/api/src/seed/seed.ts added as a mutation
    target.
